# Правила работы помощника

**Контроль соблюдения маршрута — обязанность помощника, а не автора.** Перед каждым действием выполнить следующую проверку.

1. **Задача.** Определить конкретный результат последнего поручения автора. Не запускать старый «следующий шаг» из журнала вместо нового задания.
2. **Фактическое состояние.** Проверить HEAD и существующие файлы GitHub; состояние Zotero и локальных файлов утверждать лишь по реальному выводу. Проверить, что уже сделано. Не повторять импорт, поиск или подготовку текста и не создавать дубликаты.
3. **Маршрут.** Использовать согласованный путь: Яндекс.Диск/оригиналы и Zotero → выборочная локальная обработка → допустимые материалы и результаты в GitHub. Не предлагать загрузку в чат, иной сервис, новый скрипт или смену хранилища без установленной необходимости.
4. **Граница доступа и прав.** Не утверждать доступ к диску `Y:`, Zotero Desktop, файлам на Windows или отдельным вложениям без проверки. Не публиковать секреты, частные заметки, большие сканы и полные тексты защищённых произведений в публичном GitHub без проверки прав.
5. **Исполнение.** Выполнить задание до проверяемого результата в целевом месте. Черновик только в чате, созданный RIS, запуск скрипта или предполагаемый Zotero Key не считаются завершением. После записи повторно прочитать результат и проверить HEAD/состояние.
6. **Преграда.** Если штатный путь действительно недоступен, назвать точное препятствие и **одно минимальное действие** для его устранения; не начинать самостоятельную перестройку процесса.
7. **Согласование.** Изменение утверждённой композиции, исследовательского метода, архитектуры, публичная публикация статьи и не порученные автором push/merge требуют отдельного решения автора. Явное поручение изменить документы проекта разрешает их внесение в GitHub в пределах этого поручения.
8. **Рабочий ритм.** Делать небольшой завершённый блок, не распыляться на сопутствующие исследования. Не объявлять непроверенное проверенным.

Границы научной достоверности определяет `governance/PROJECT-INSTRUCTIONS.md`; содержание статьи — `article/OUTLINE.md`; стиль — `governance/WRITING-GUIDE.md`. Не копировать эти требования сюда.
