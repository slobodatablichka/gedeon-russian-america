# Zotero — штатный рабочий маршрут

**Источник истины для библиографии — Zotero Desktop**, не черновой RIS и не память чата. Коллекция проекта и её дочерние коллекции: **`YWQFHUER`**. Локальный каталог `C:\Projects\Gedeon`. Пользователь запускает Zotero Desktop на своём компьютере; помощник не имеет к нему автоматического доступа.

## Проверка записей
Из PowerShell в каталоге `C:\Projects\Gedeon`:

```powershell
.\scripts\check-zotero-local.ps1
```

Успех: `OK Zotero Desktop local API; collection=YWQFHUER; items=N`. Скрипт через локальный API и `curl.exe` **только читает**; создаёт `research/zotero/local-catalog.json` **на компьютере пользователя**, не публикует его в GitHub и не синхронизирует с помощником. Для фиксации ключа помощником нужен проверенный вывод или разрешённые к публикации метаданные. **Не просить ключ облачного API** для штатной проверки.

## Добавление источника
Сначала проверить существующую запись и дубликаты. При отсутствии создать полноценную запись (проверенный RIS-импорт либо согласованный способ), поместить в коллекцию и проверить PDF-вложение. **Подготовленный RIS ≠ запись Zotero; наличие библиографии ≠ проверка содержимого PDF.** После импорта снова выполнить штатную проверку и использовать полученный `item.key` в реестре и карточках. Не угадывать ключ.

## Если проверка не работает
1. Убедиться, что Zotero Desktop запущен. При необходимости проверить:
```powershell
curl.exe --noproxy "*" --http1.1 -i --max-time 15 "http://127.0.0.1:23119/api/users/0/collections?limit=1"
```
2. Если `curl` отвечает, не менять API-настройки: искать сбой в скрипте. **`HTTP/1.0 200 OK` — успех.**
3. Облачный `scripts/export-zotero-research.ps1` — отдельный резервный способ с ключом, не применять по умолчанию.
