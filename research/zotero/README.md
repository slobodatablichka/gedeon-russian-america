# Zotero: установленный порядок подключения

**Принято 2026-10-27 после реального успешного теста.** В проекте «Гедеон — Русская Америка» основной источник библиографических метаданных — открытый Zotero Desktop, подключаемый через **локальный HTTP API и curl.exe**. **Ключ облачного Zotero Web API для этого не нужен.**

## Исходные параметры
- Репозиторий: `slobodatablichka/gedeon-russian-america`; локально `C:\Projects\Gedeon`; ветка `main`.
- Zotero Desktop в успешном тесте: **10.0.6**.
- Сервер: `http://127.0.0.1:23119/api/users/0`.
- **Постоянный ключ корневой проектной коллекции: `YWQFHUER`.** Не искать эту коллекцию по кириллическому имени внутри PowerShell 5.1; имя может быть прочитано с неверной кодировкой.
- Проверенный скрипт: `scripts/check-zotero-local.ps1` (исправлен до commit `cb5e4fe`).
- Учитываются корневая коллекция и **все её дочерние коллекции**; записи дедуплицируются по реальному `item.key`, вложения/заметки/аннотации не выгружаются.

## Штатная процедура для каждого нового чата
1. Прочитать `START.md`, `AGENTS.md`, `governance/PROJECT-INSTRUCTIONS.md`, `governance/CURRENT-STATE.md`; проверить актуальный GitHub HEAD.
2. При необходимости обновить локальную копию `git pull --ff-only` (не делать слепой pull при конфликте или незавершённых локальных изменениях).
3. Пользователь запускает Zotero Desktop; команда в PowerShell из каталога проекта:

```powershell
Set-Location 'C:\Projects\Gedeon'
.\scripts\check-zotero-local.ps1
```

4. Критерий успеха — `OK Zotero Desktop local API; collection=YWQFHUER; items=N`; тест **2026-10-27 завершился с N=8**. Это актуальный снимок *на дату проверки*, не обещание, что всегда будет 8 записей.
5. Скрипт создаёт **локальный** `research/zotero/local-catalog.json`, в котором есть реальные `item.key`, названия, типы и коллекции. **У помощника нет автоматического доступа к локальному JSON через GitHub**. Для актуальной сверки ключей передать файл через утверждённый способ или опубликовать только проверенные метаданные по согласованию. Не придумывать Item Keys по названиям.
6. Только после реального доступа к каталогу помощник вносит ключи в SOURCE-REGISTER/EVIDENCE и проверяет наличие новых импортированных записей.

## Диагностика — один шаг за раз
- Сначала протестировать **непосредственный curl**, если скрипт не работает:
```powershell
curl.exe --noproxy "*" --http1.1 -i --max-time 15 "http://127.0.0.1:23119/api/users/0/collections?limit=1"
```
- `HTTP/1.0 200 OK` **является успехом** (в ходе успешного теста Zotero вернул именно HTTP/1.0); не требовать HTTP/1.1 или HTTP/2.
- Если прямой curl успешен, **не трогать настройки Zotero и API-ключ**: искать ошибку в PowerShell-скрипте.
- Исторические ошибки устранены: `Invoke-RestMethod` разрывал соединение при работающем curl — поэтому используем curl; русское имя коллекции в UTF-8 скрипте на Windows PowerShell 5.1 превращалось в «Р…» — поэтому коллекция выбирается по `YWQFHUER`; `return ,$out` создавал вложенный массив и объединял 17 ключей в один URL — поэтому `Get-All` возвращает `return $out`.
- Если curl не отвечает, тогда отдельно проверять, запущен ли Zotero и включена ли возможность локального взаимодействия. Не переходить автоматически к Web API.

## Чтение и запись — отдельно
- `check-zotero-local.ps1` **только читает** и пишет локальный JSON. Он **не создаёт и не изменяет записи Zotero**, не выполняет двусторонней синхронизации.
- Добавление источников сейчас проводится через **проверенный RIS-импорт** либо через отдельный согласованный механизм записи. При импорте проверять дубликаты и нахождение в правильной проектной коллекции.
- `scripts/export-zotero-research.ps1` использует **облачный Zotero Web API** и `ZOTERO_API_KEY`; это **резервный/отдельный способ**, не рекомендовать по умолчанию.
- Никаких ключей API, закрытых заметок или сканов в публичный GitHub без отдельной проверки. Отчёт об успешном локальном запросе не равен публикации JSON и не означает, что каталог уже доступен помощнику.
